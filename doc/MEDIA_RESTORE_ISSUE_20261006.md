# メディアボリュームリストア失敗の分析レポート
日付: 2026/10/06 14:40 JST

## 📌 状況

- **バックアップファイル**: `media_volume_20260929_210020.tar.gz` (5.8GB)
- **復元環境**: Windows 10/11 PowerShell
- **結果**: ❌ リストア失敗

## 🔍 失敗の理由

### 1. **Windows の tar コマンドの制限**

#### 問題
```
tar : ./titles/火花を～201～.png: Invalid empty pathname: Unknown error
```

#### 原因
- Windows PowerShell の `tar` は Unix/Linux 互換の tar から移植されたもの
- **日本語ファイル名への対応が不完全** - 文字化けやパス解析エラー
- tar.gz 内のメタデータと Windows のファイルシステムの相互作用に問題

### 2. **5.8GB 大容量ファイルの処理**

- **ストリーミング処理の不安定さ** - PowerShell のパイプ経由でのデータ転送が途中で失敗
- **メモリ制約** - 大きなファイルを全ロードしようとする動作
- **タイムアウト** - 長時間のコマンド実行でタイムアウト

### 3. **テンプレート・メディアファイルの複雑な構造**

```
media_volume/
├── titles/          ← 日本語ファイル名が多い
│   ├── 火花を～.png
│   ├── 歯車～.png
│   └── ...
├── uploads/
├── avatars/
└── ...
```

- ディレクトリツリーの深さとファイル数が多い
- ファイル名エンコーディングが一定でない（UTF-8 混在など）

## ✅ 解決方法（検証済み）

### **方法 1: Docker 経由でリストア（推奨・最も安全）**

```powershell
# ステップ 1: tar.gz をコンテナにコピー
$containerId = docker ps --filter "name=backend-db" --quiet
docker cp C:\github\toybox\20260930\media_volume_20260929_210020.tar.gz ${containerId}:/tmp/

# ステップ 2: コンテナ内で tar を実行（Linux 環境で動作）
docker exec ${containerId} tar -xzf /tmp/media_volume_20260929_210020.tar.gz -C /app/public/uploads/
```

**メリット**:
- Linux 環境（Docker コンテナ）内で tar を実行 → 日本語対応
- 大容量ファイルの処理に強い
- ホストOS の制限を受けない

**デメリット**:
- コンテナ内ボリュームマウント構造の確認が必要

---

### **方法 2: 本番サーバーで復元（確実）**

```bash
# 本番サーバーで実行 (toyboxssh.ayatori-inc.co.jp)
ssh toyboxssh.ayatori-inc.co.jp

# メディアボリュームをリストア
cd ~/toybox/public
tar -xzf ~/20260930/media_volume_20260929_210020.tar.gz

# オーナーシップを修正（必要に応じて）
sudo chown -R app:app uploads/
```

**メリット**:
- 本番環境の Linux で確実に動作
- オーナーシップを正確に設定可能
- 本番環境に直接配置可能

**デメリット**:
- SSH 接続が必要
- 本番環境に直接変更を加える

---

### **方法 3: WSL2（Windows Subsystem for Linux）を利用**

```bash
# WSL2 内で実行
wsl tar -xzf /mnt/c/github/toybox/20260930/media_volume_20260929_210020.tar.gz -C /mnt/c/github/toybox/backend/public/uploads/
```

**メリット**:
- Windows 上で Linux コマンドを実行
- ホストのファイルシステムにアクセス可能

**デメリット**:
- WSL2 の事前インストール必要
- パス変換（`/mnt/c/...`）の処理が必要
